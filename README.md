# grill — 計画を1問1答で詰め切るスキル

計画・意思決定・設計を、**1ターンに1問ずつ**問い重ねて詰め切る Claude Code 用スキルです。
「いい感じにやっておいて」で走り出す前に、穴を先に潰すために使います。

> 作成: [ajtcsolution](https://github.com/ajtcsolution)（日本語で一から設計したオリジナルです）。
> 英語圏で流通している同名系のスキル `grill-me` / `grilling` とは別物です。

**このスキルは実行しません。** 合意に達するまで、問うだけです。

---

## なぜ作ったか

計画が失敗する原因の多くは、実装力ではなく**決める前に詰めていないこと**にあります。
特に抜けやすいのが次の2つです。

- **失敗条件** — どうなったら失敗と判定するかを、測れる形で決めていない
- **撤退条件** — いつ・何を見てやめるかを、始める前に決めていない

この2つが無いまま走り出した計画は、失敗しても失敗と気づけません。
`grill` は完了条件の6項目にこの2つを含め、**ここを飛ばして合意させない**ようにしてあります。

---

## 特徴

| 作法 | 中身 |
|------|------|
| 1ターン1問 | 質問を並べない。直前の回答で一番引っかかった一語を掴んで一段掘る |
| 推奨解を必ず添える | 「仮説ですが、おそらく〇〇では？」と自分の案を置き、肯定・否定・修正で返せるようにする。丸投げの「どうしますか？」を禁じる |
| 詰めるのは案であって人ではない | 相手の人格・能力・過去の不作為には触れない。厳しさは問いの深さで出し、言葉の強さでは出さない |
| 事実は聞かず自分で調べる | ファイル・ログ・設定を読めば分かることは質問しない。問いは「その人にしか答えられない決定」に集中させる |
| 深掘りラダー | 対象 → 動機 → 影響を受ける人 → 既存のやり方 → 不満の核 → 前提 → 前提が崩れたら → 代替案 → 失敗条件 → 撤退条件 の分岐ツリーを、浅いまま降りずに潰す |
| 合意まで実行しない | コードを書かない。ファイルを変えない。最後に合意サマリと「詰め切れなかった点」を出して止まる |

## インストール

```bash
git clone https://github.com/ajtcsolution/kabeuchi-skill.git
cp -r kabeuchi-skill/skills/grill ~/.claude/skills/
```

Windows（PowerShell）:

```powershell
git clone https://github.com/ajtcsolution/kabeuchi-skill.git
Copy-Item -Recurse kabeuchi-skill\skills\grill $env:USERPROFILE\.claude\skills\
```

プロジェクト単位で使う場合は `~/.claude/skills/` の代わりに `<プロジェクト>/.claude/skills/` に置きます。

> **名前の衝突について**: コミュニティで流通している `grill-me` / `grilling` スキルを既に入れている場合でも、
> こちらはスキル名が `grill` なので共存できます。

## 使い方

```
/grill
```

または、詰めたい対象を直接渡します。

```
/grill 来期の価格改定プラン
/grill この認証まわりの設計
```

以降、問いが1つずつ飛んできます。答えると次の問いが来ます。
完了条件6項目（目的 / 対象 / 前提 / 代替案 / 失敗条件 / 撤退条件）が揃うと、合意サマリが出て止まります。

途中でやめたいときは「今日はここまで」と伝えてください。
そこまでの合意サマリと、残っている問いが出ます。

---

## 完了条件

| # | 要素 | 確認する問い |
|---|------|------------|
| 1 | 目的 | なぜこれをやるのか。やらなかったら具体的に何が困るのか |
| 2 | 対象 | 誰のための決定か。影響を受ける人を1人に名指しできるか |
| 3 | 前提 | 何を真だと仮定しているか。それは検証済みか、思い込みか |
| 4 | 代替案 | 採らなかった案は何か。なぜ捨てたのか |
| 5 | 失敗条件 | どうなったら失敗と判定するか。測れる形で言えるか |
| 6 | 撤退条件 | いつ・何を見てやめるか。やめる判断を誰がするか |

## 作者

[ajtcsolution](https://github.com/ajtcsolution) が作成しました。

独自に設計した点は次のとおりです。

- 推奨解（たたき台仮説）を必ず添える作法と、種出しの問いには添えないという例外
- 「人ではなく案を詰める」トーン規定
- 完了条件6項目（特に**失敗条件・撤退条件**）による明示的な終了判定
- 深掘りラダーの分岐ツリー化
- 合意サマリと「詰め切れなかった点」の出力形式

日本語での運用知見は、起業壁打ちスキル `shisaku` の実運用から取り出しています。
関連: [ajtcsolution/shisaku-skill](https://github.com/ajtcsolution/shisaku-skill)
